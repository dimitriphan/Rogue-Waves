# Shared vessel-mod kit

Compiled into every vessel mod of the project and every part of the Rogue Waves pack (`TDS_Mod/ModSource/Shared/`); each build script renames the `ModKit`
prefix to `<Name>Kit`, so every mod gets its own copy of the types and none collide.

| File | Provides | Used as |
|---|---|---|
| `ModKitJournal.cs` | `ModKitJournalSpec`, `ModKitJournalBuilding`, `ModKitJournalUpgrade`, `ModKitJournalUnit`, `ModKitVesselJournal` (builds all of a vessel's journal pages), `ModKitVesselTabs` (one tab per vessel on every vessel page) | `docs/06_JOURNAL.md` |
| `ModKitBoat.cs` | `ModKitBoat.LateUpdate(heroId)`: one boat spot per vessel, every vessel clickable on a crowded deck (staggered rows), the vessel's button unlocked; `ClickReport` for self-tests | call it from the mod's `LateUpdate` |
| `ModKitTowers.cs` | `ModKitTowers.Fit`: a tower's hit prefab and range anchor at the brain's eye height, so the game draws one centred range; `RangePreview` | once per buildable, where its template is set up |
| `ModKitCombat.cs` | `ModKitCombat.Hurt`/`Mark`: hits from the mod's own code that deal damage and count as hits (kills, Aegis regen); kit 1.12: `SetMulti`, a hit hook's new Damagemulti on a copy of the hit's data (pitfall #30) | for every hit the mod deals itself; `SetMulti` in every hit hook that changes a blow |
| `ModKitPack.cs` | Kit 1.6, the pack: `Join(part, version)` registers a part in one `RogueWaves_Registry` object and warns when parts disagree on pack version or kit; `Has(part)` (another part joined); `Taken(heroId)` (a standalone copy already loaded), `Mark(job)` (one part does a pack-wide job), `Notice` (an error the player sees) | the repository's `docs/PACK.md` |
| `ModKitTides.cs` | Kit 1.6: `MapStart`, `Tide(n)` and `MapEnd(result)` events, host only, polled from `Game_Mapvars` (a rewind resets without firing); kit 1.7: `Break(wave)` and `InBreak`, from the Tide table's row (`Entry - 1`, pitfall #121); kit 1.9: no `Tide(0)` at a map's start | call `Update()` from the part's `Update` |
| `ModKitCounter.cs` | Kit 1.6: a number shown on an entity as a stat (`Set`/`Get`), e.g. Argo's Fathom | |
| `ModKitDirections.cs` | Kit 1.6: Directions, the Rogue mode's per-vessel upgrade picks: ids, `Make`, `Has`, `Grant` (host; 1.6 grants on the team's Core, which makes a Direction team-wide; kit 1.7 moves it per player onto the vessel, `docs/15` §14.1) | `docs/15` |
| `ModKitFocus.cs` | Kit 1.6: the F-key fix (the first F after a respawn selects the vessel again), installed once per pack; kit 1.11: notices the respawn (pitfall #157), `Installed` (this part's copy runs it) | call `Update()` from the part's `Update`; `docs/15` §9 |
| `ModKitUtil.cs` | Kit 1.8: the helpers every part had its own copy of: the database (`Folder`, `Load`, `Heroentry`), beings and stats (`BeingName`, `Owner`, `Team`, `Alive`, `Pos`, `Stat`, `Health`...), queries (`Foes`, `Friends`, `Tagged`, `Area`, `FoesNear`), `Hurt`/`Heal`, debuff looks (`Debuff`, `RemoveDebuff`, `ForgetLooks`), costs and json fields, script carriers (`Script`), content building (`Strip`, `AddSkin`, `CollectUpgrades`) and the hit chain (`Front`, `Unfront`, `Listen`: a handler kept first in `Oninteract`); kit 1.12: `SlowOn` (a held slow with the 10% floor, pitfall #79), aura (`Auras`, `Purse`, `Gain`, `Give`), and `Keep` makes a Health mod again instead of filling the stat (`docs/17` §2.1); kit 1.14: `Front` leaves a handler already ahead of the game's own where it is (pitfall #168) | `ModKitUtil.Pos(m)`; a part keeps only what names it (`Retag`, `Clone`, `Warn`, `Later`) |
| `ModKitAssets.cs` | Kit 1.8: the part's asset library (`<Part>Assets_Library` in its prefab): `Find(mod, part)`, sheets, models, effects, clips, `Frames`/`Single`/`Anim`/`Unit` Spriteobjects, the boat's `Worldsprite` (`S<Part>Sheet`), `Pixel` icons (the part's palette; kit 1.10: `CommandIcon`, a box for command icons, and `Boxed`; kit 1.15: `TinyLooks(vp, being)`, Diorama's tiny look as skins named after the being, `TinyName`, `Scaled` (a Spriteobject at another size), `docs/17` §11 rule 19), `Play(clip, at, volume)`, `Effect` | `ModKitAssets.Find(<Part>Mod.Instance, "<Part>")` at boot; the part keeps its hero sheets, icons, tower material and sound levels |
| `ModKitTest.cs` | Self-test builds only (`MODKIT_TEST`, set by the build scripts with any `<NAME>_SELFTEST`): the pinned test map (`PickNode`), the map snapshot (`MapDump`), placement searches that log why and a picture of the ground (`Spot`, `FoeTile`, `SpawnFoe`, `Picture`), and the `TEST SETUP` outcome | `docs/08` |
| `ModKitLight.cs` | Kit 1.13: a map's lighting changed while it runs: a `Look` (linear fog colour and distances, fixed or as multiples of the camera's distance to the ground; the ambient sky, horizon and ground colours; the sun's colour, strength and direction), `Set(look, seconds)` fades to it and holds it against the game's own lighting call, `Grade(name, sky)` borrows a stock lighting group's post-processing whole, `Restore(seconds)`, `Lamp` (a point light), the 55 stock groups by name (`Group`, `Groups`, `MapOwn`); read from code, not yet run in game (pitfall #167: never touch `Bl_Lighting_Group.Profile`) | call `Update()` from ONE part's `Update` on every machine (the mode's); kit `docs/16` §7 |
| `ModKitPlay.cs` | Play builds only (`MODKIT_PLAY`, never set by a build script: `-Define <NAME>_PLAY,<NAME>_SHOTS,MODKIT_PLAY,MODKIT_TEST`): a virtual player for a vessel's play test. Input System events on the game's own mouse and keyboard reach the HUD, the map and the keys as a hand does; aimed clicks (`ClickTile`, `ClickThing`); a player's moves (`SelectVessel`, `Build`, `Upgrade`, `Sell`, `Command`, `WalkTo`, `FastForward`); `Build` and `Upgrade` fall back to the command and log `FALLBACK` when the click didn't take, the others log that the move by hand failed; the foes' lanes (`PlanLanes`), the map loop (`Plans`, `Scenario`) | each vessel's `Code/98_Play.cs`; the repository's `docs/reports/PLAYTEST_2026-10-26.md` |
| `ModKitBrain.cs` | Kit 1.16: `ModKitBrain`, the base of a buildable's server brain: waits for the entity's stats, commands and radio, then `Setup()`, `Replay(up)` for each upgrade it came with, `Started2()`, `BuiltLook()` after `BuiltLookDelay` (pitfall #158), and `Frame()` every frame; a `Frame` that threw is skipped, a start-up that threw stops the brain. `StartedAfterUpgrades` chooses whether the replay is heard before `Started` is set. `ReadParam` turns one upgrade number into a modifier or a kept param. `ModKitFaults(tag[, sharedLog])`: the error counter (pitfall #80) | a vessel's building base derives from it (`YosseleBuilding`, `SpoolBuilding`, `UloeBuilding`, `ArgoTowerBrain`); any brain holds a `ModKitFaults` |
| `ModKitBrainRules.cs` | Kit 1.16, a rules file (no engine type; `rules_check.py` K1-K8): `ModKitStreak` (the 600-frame stop rule), `ModKitUpgrades` (the upgrade keys a building holds and its kept numbers: `Add`, `Has`, `Keep`, `Param`, `Split`, `Clear`) | through `ModKitBrain` and `ModKitFaults` |

## Compatibility rules (several mods run the kit at once)

- **Tab order** must never change: shipped vessels first (`Hero_Smacky`, `Hero_Snosno`, `Hero_Buster`, `Hero_Boutman`,
  `Hero_Fie`), then mods by id (ordinal). Argo 1.0 has its own copy with the same rule.
- **Boat layout** must be the same in every mod built with kit 1.4 or later (every mod sets positions every frame; two
  algorithms that disagree make spots flicker): change `ModKitBoat`'s layout constants only in a kit release and rebuild
  every vessel. Kit 1.4 names every spot like the shipped ones, which makes 1.0-1.3 copies in older builds leave the
  spots alone, so a 1.4 build can be installed beside older ones.
- When you change the kit: bump the version here and in the file header, keep the two rules, compile every mod in the
  project (`Build-<Name>Mod.ps1` for each), and rebuild + re-export the mods you ship.
