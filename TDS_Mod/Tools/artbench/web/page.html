How an edit gets back into the mod

  1. Pick a row and download it. You get a .zip holding one .aseprite file: the row's frames, one tag per animation, and the part's palette. A model comes as a .zip holding a .glb that Blender opens with File › Import › glTF.
  2. Edit it and save. Keep the canvas size and each tag's frame count. Extra layers are fine; hidden layers are left out. In Blender, keep the moving parts' names (Pivot, Gun) and export as glTF binary (.glb).
  3. Drop the file back on the same row or model here. The page checks it and shows the changed frames next to the current ones. Press Send to the mod: it is kept here, marked waiting.
  4. Say "bring in my art edits" in the project. A thread reads every waiting edit, writes it into the repo, rebuilds this page and runs the cloud compile.
  5. It opens a pull request with a reviewer. It merges once the reviewer approves and the compile is clean, and the edit shows merged.
  6. The next PC round shows it in the game, and the edit shows seen on the PC.

Where an edit goes

Sheets the builder merges (most vessel sheets): your frames go into ModSource/<Part>/Aseprite/<sheet>.aseprite. The builder swaps in only the frames you changed. Frames you left alone keep following the code, and a mirrored facing (v1 from v0, v3 from v2) follows your edit unless you edited it too.

Sheets kept as files (the Cordyfriend, the Thread Head, Uloe's lit sheet, the tuft, Vendcint and the mode icons): the changed frames are written into that file. A code-drawn sheet becomes a file this way, so later code changes to it stop showing.

Models: the edited mesh is saved next to the part's models and replaces the code's shape for that model. Colours snap to the nearest of the 64 palette swatches. The builder support for this comes with the first model edit, which also needs a PC round.
